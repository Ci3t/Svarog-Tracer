This is a **community-driven theorycrafting framework** that claims relic upgrades in **Honkai: Star Rail** follow **structured, time-dependent pseudo-random “strings”**, and that by **recording, translating, and timing upgrades**, players can **significantly increase the odds of hitting desired substats** — without cheating.

## 🎯 Core premise

* Relic upgrades are **not fully random**.
* Instead, they follow a **long underlying sequence (“string”)** of numbers (1–4), where each number corresponds to **which substat line gets upgraded**.
* Every upgrade advances you **one step forward** in that string.
* **Time (especially 15-minute windows)** also shifts or repositions your place on the string.

So while you don’t control the string itself, you *can*:

* Detect which parts of it you’re currently on
* Predict short-term behavior
* Exploit higher-probability windows

## 🔢 How “strings” work

* A **string** is read as a sequence like `4 1 3 2 x`
* Each number = which substat line is upgraded (1–4)
* Strings are usually analyzed in chunks of **2–4 digits** (e.g. `44`, `421`, `4333`)
* The 5th digit is usually unreliable → treated as random

### Important mechanics

* **Adding a new substat resets the string**
* **Continuing upgrades carries the string forward**
* Leaving the character screen **breaks tracking**
* Strings can carry **across relics** if you don’t reset them

## 🔁 Translation concept (this is key)

The document introduces **translation**, which means:

> The string represents *relative movement*, not absolute substat lines.

Example:

* A pattern like `444` really means: `x, x+0, x+0`
* If your desired stat is on line 2 and you start the string on line 2 →
  `444` becomes `222`

This lets you:

* Use **popular global patterns**
* Translate them to **your relic’s specific layout**
* Force upgrades onto crit lines even if the raw pattern isn’t “2” or “3”

## 🛠 Upgrade strategies described

Several approaches, from simple to advanced:

### 1. Basic method

* Just roll during times where certain lines dominate
* Low control, easy to use

### 2. Long-string biasing (preferred)

* Use longer strings (421xx, 4333x, etc.)
* Longer strings show **stronger bias**
* Avoid resetting the string
* Swap relics to keep “bad” lines off the upgrade

### 3. Predictive play

* Watch how often a group repeats before switching
* Assume patterns flip after:

  * Too much time
  * Too many hits in the same group
* Upgrade at consistent speed

### 4. Alternative methods

* Distribution-based (Esme / Whiscat)
* Matching-data method (Kiyoko)
  These focus more on **avoiding bad lines** than forcing good ones.
